## 1. Scope and exclusions

**In scope (M3.2):**
- `att` schema additions: `devices`, `device_user_map`, `punches`, `punch_voids`, `ingest_batches` — additive only, no ALTER on M3.1 tables.
- Punch ingestion from four sources: **device push API** (biometric terminals), **self punch** (employee mobile/web check-in), **manual punch** (HR/admin entry), **CSV import** (bulk/offline device sync).
- Idempotency + duplicate detection at every entry point.
- Device management + employee↔device-code mapping (incl. back-fill of unmapped punches on map creation/change via the `attendance.device.map` job).
- Append-only enforcement for raw punches; voids instead of deletes.
- Raw punch viewer with filters, import history + error monitoring, device management UI.
- Permission seeding, scoped data access, audit coverage.

**Explicit exclusions (later milestones):**
- No attendance calculations: no `attendance_days`/`attendance_days_ledger`, no late/early/OT/absent/payable computation, no work-duration derivation. (M3.3.)
- No regularization, no approval workflows, no correction flows beyond admin void. (M3.4+.)
- No pairing/punch-in→out sessionization beyond storing raw direction.
- No `shift_based` deep test cases land as *implementation* here — but M3.2 adds the required dedicated `shift_based`/`RotationRule` resolver tests deferred from M3.1 (recorded obligation).
- No real vendor SDK integrations (ZKTeco push protocol, eSSL, Suprema); device integration ships as the documented HTTP push contract + file import adapters.
- No changes to M1/M2/M3.1 behavior or tables.

## 2. Database design (new `att` objects)

All tables additive in `att`, tenant-local, FKs to `core.employees`/`core.branches` as noted. New migration `AttendanceCore` (single EF migration, approval-gated per tenant).

### 2.1 `att.devices`
Terminal/device master.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| code | text UNIQUE | tenant-unique device code, e.g. `BIO-HQ-01` |
| name | text | |
| vendor | text null | informational |
| branch_id | uuid null → `core.branches` | physical location; feeds data-scope for device punches |
| protocol | text | `push_api` \| `pull_poll` \| `file_import` (M3.2 implements push_api + file_import; pull_poll is a declared seam) |
| timezone_mode | text | `utc` (payload already UTC) \| `device_local` (interpret wall-clock in `device_timezone`) |
| device_timezone | text | IANA tz, required when `timezone_mode = device_local` |
| token_hash | text UNIQUE | SHA-256 of bearer token (token shown once at create/rotate, never stored) |
| credential_ref | text null | external secret reference for pull_poll devices |
| last_seen_at | timestamptz null | updated on successful push |
| is_active | bool | soft disable |
| created_at/updated_at/by | audit cols | standard |

### 2.2 `att.device_user_map`
Maps a device's own user/badge code to an employee, with effectivity.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| device_id | uuid → `att.devices` | |
| device_user_code | text | the ID enrolled on the device (e.g. fingerprint ID "1002") |
| employee_id | uuid → `core.employees` | `ON DELETE RESTRICT` (per M3.1 hardening direction) |
| effective_from / effective_to | date | supports badge reassignment history |
| created_at/by | audit cols | |

Constraints: `UNIQUE (device_id, device_user_code, effective_from)`; gist exclusion on `(device_id, device_user_code)` × daterange preventing overlapping mappings (same exclusion-constraint pattern as M3.1 assignments). Resolution order at ingest: map effective on punch date → else punch stored unmapped.

### 2.3 `att.punches` — append-only raw store
One row per punch event, immutable, preserved verbatim.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| employee_id | uuid null → `core.employees` | NULL = unmapped device punch; back-fillable once |
| punched_at | timestamptz | **instant** of the punch, UTC normalized |
| local_wall_time | timestamp | raw wall-clock as emitted by device/import, pre-normalization |
| source | text | `device` \| `self` \| `manual` \| `import` (`regularization` reserved, unused) |
| direction | text | `in` \| `out` \| `unknown` |
| device_id | uuid null → `att.devices` | device provenance |
| device_user_code | text null | raw code as received |
| ingest_batch_id | uuid null → `att.ingest_batches` | which upload/push call produced the row |
| dedup_key | text UNIQUE | SHA-256(source, device_id, device_user_code, employee_id, punched_at-to-second) — idempotent re-push safe |
| geo_lat / geo_lng | double null | self/mobile punches |
| geo_accuracy_m | int null | |
| ip_address / user_agent | text null | self/manual provenance |
| ref_request_id | text null | caller-supplied correlation |
| note | text null | mandatory for `manual` |
| created_at/by | audit cols | received-at = `created_at` (never updated) |

Indexes: `(employee_id, punched_at)`, `(device_id, device_user_code)`, `(ingest_batch_id)`, `punched_at` BRIN (append-ordered time series), `UNIQUE (dedup_key)`.

**Immutability:** trigger `trg_punches_append_only` — UPDATE/DELETE rejected except the single `employee_id` back-fill column on NULL→non-NULL transitions (enforced via `OLD.employee_id IS NULL AND NEW.employee_id IS NOT NULL` column guard). No other column may change. Corrections = `punch_voids` row + corrected re-entry.

### 2.4 `att.punch_voids`
Void markers (punch row stays; computation phases ignore voided punches).

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| punch_id | uuid UNIQUE → `att.punches` | one void per punch |
| reason | text | mandatory |
| voided_by / voided_at | audit cols | |

### 2.5 `att.ingest_batches`
One row per ingestion attempt — the retry/failure tracking backbone.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| source | text | `device` \| `import` \| `self` \| `manual` |
| device_id | uuid null | |
| file_id | uuid null → `files` | CSV import payload via FileService |
| idempotency_key | text UNIQUE | device `Idempotency-Key` header or import dedup key |
| received_count / accepted_count / duplicate_count / rejected_count | int | tallies |
| status | text | `processing` \| `completed` \| `failed` |
| error_summary | text null | first-N reject reasons, JSON |
| created_at/by, completed_at | | |

**Duplicate + idempotency model:** punch-level `dedup_key` UNIQUE (content dedup, catches re-import of the same device rows even under different batches) + batch-level `idempotency_key` UNIQUE (call dedup, safe device retry). Re-push of an identical batch: key hit → return stored counts, zero new rows. Partial-duplicate batch: accepted=NEW rows only, duplicates counted, **no valid punch is ever silently lost** — a punch that dedups but maps to a different (now-mapped) employee still gets its employee_id back-filled.

**Unmapped punches:** stored with `employee_id NULL`, `device_user_code` kept raw. The `attendance.device.map` job re-scans unmapped punches for that device and back-fills employee_id when a map row appears — zero data loss for late registrations.

**Timezone handling (normative):**
- `punched_at` (timestamptz) is the canonical instant, always UTC.
- `local_wall_time` (timestamp) preserves exactly what the device emitted — never recomputed, never lost.
- `timezone_mode=utc`: payload interpreted as UTC directly. `device_local`: `local_wall_time` interpreted in `device_timezone` → `punched_at`. Ambiguity around DST fall-back resolved to first occurrence; documented. Unknown/garbage timestamps → reject row into batch error counts (never drop silently).
- Self punches: client sends its wall-clock + offset; server validates skew ≤ 24h and stores both.
- Overnight shifts: punches are stored as pure events with no day attribution — shift/date grouping is M3.3's problem, raw store is time-ordered only.

## 3. APIs

Tenant-scoped under `/api/v1/attendance`. `Result` → ProblemDetails pattern; data scope via `IDataScopeService.ApplyEmployeeScope`.

### Devices (`attendance.devices.manage`, sensitive)
| Method | Path | Notes |
|---|---|---|
| GET | `/devices` | list + filters (branch, protocol, active) |
| POST | `/devices` | create → returns plaintext token **once** |
| PUT | `/devices/{id}` | update name/branch/timezone/protocol fields |
| POST | `/devices/{id}/rotate-token` | re-issue token; old hash invalidated |
| GET/PUT | `/devices/{id}/user-map` | list/replace mappings with effectivity |
| POST | `/devices/{code}/punches` | **device ingestion endpoint** — `Authorization: Device <token>` + `Idempotency-Key` header; body = array of `{device_user_code, timestamp, direction}`; response `{batch_id, accepted, duplicate, rejected, rejections[]}` |

### Punches
| Method | Path | Permission | Notes |
|---|---|---|---|
| POST | `/punches/self` | `attendance.my.punch` | own check-in; geo + optional geofence validation against branch coords; skew check |
| POST | `/punches/manual` | `attendance.punches.manual` (scoped) | note mandatory; `ref_request_id` for caller idempotency |
| POST | `/punches/import` | `attendance.punches.import` (scoped) | `{file_id, device_id?, column_mapping}` — file already uploaded via FileService; parses async per existing job pattern |
| GET | `/punches` | `attendance.view` (scoped) | filters: employee, device, source, direction, date range, mapped/unmapped, incl/excl voided |
| POST | `/punches/{id}/void` | `attendance.punches.manual` (scoped) | reason mandatory |
| GET | `/ingest-batches` / `/ingest-batches/{id}` | `attendance.view` | import/push history + error detail |

### Device authentication (new middleware seam)
`Authorization: Device <token>` — tenant resolved by request host (existing tenant middleware) → device lookup by `token_hash` in that tenant's `att.devices`, `is_active` check, `last_seen_at` update. No session/cookie/CSRF. Rate-limited. Unknown token → 401; token used on wrong-tenant host → 401 (cross-tenant isolation by construction). This is a *new* auth kind confined to the single `pushes` endpoint; nothing else accepts device tokens.

### Jobs
- `attendance.device.map` — enqueued on user-map create/update: back-fills `employee_id` on NULL punches matching device+code within effectivity.
- `attendance.device.offline` — scheduled sweep: device `protocol=push_api` with `last_seen_at` older than configured threshold → notification record (uses existing notification infra).
- Import processing job — parses CSV into punches with per-row error capture into `ingest_batches.error_summary` (mirrors calendar-days import pattern).

## 5. UI pages and workflows

New **Punches** tab group in the Attendance area (`/attendance`), alongside existing Admin:

1. **Raw Punches** (`/attendance/punches`) — filterable grid: date range, employee picker (respects data scope), device, source chip, direction, mapped/unmapped toggle, voided toggle; detail drawer shows all provenance (device code, batch, geo, dedup key, wall clock vs UTC); void action (permission-gated).
2. **Import** (`/attendance/import`) — FileService upload → column-mapping step (device code / employee code / timestamp / direction fields) → submit → progress; links into batch detail.
3. **Import History** (`/attendance/imports`) — `ingest_batches` list: source, counts (received/accepted/duplicate/rejected), status, error expansion, retry affordance.
4. **Devices** (`/attendance/devices`) — device cards/table: code, branch, protocol, last-seen badge, token rotation (plaintext shown once in a copy dialog), user-map editor (badge code → employee picker, effective dates).
5. **My Punches** (`/attendance/my`) — self check-in/out button (geo permission flow) + own punch list; menu entry gated on `attendance.my.punch`.

No calculation widgets — the viewer shows raw events only. Menu `AnyPermissions` extended; module gating unchanged.

## 6. Device integration approach

- **Push model (implemented):** biometric terminals (or a vendor gateway/agent) `POST /attendance/devices/{code}/punches` with device token + idempotency key. Contract documented in `docs/integrations/device-push.md`: payload schema, retry semantics (network failure → same Idempotency-Key retry; server returns stored batch), clock guidance.
- **Offline sync via import (implemented):** device exports (CSV/Excel→CSV) go through `/punches/import` with `device_id` attached — same dedup guarantees; covers devices without HTTP push.
- **pull_poll (seam only):** `protocol` value reserved; a `credential_ref` + poller job shape designed but not implemented (M3.x) — keeps the schema future-proof without shipping a vendor SDK.
- **Vendor specifics deferred:** no ZKTeco/eSSL native protocols; integration guide recommends a thin on-prem gateway translating to our push contract.

## 7. Test plan

API tests (Testcontainers, existing harness):

- **Dedup/idempotency:** same device batch re-pushed with same key → identical counts, zero new rows; same punches under *different* key → content dedup still rejects duplicates; manual re-submit with same `ref_request_id` rejected; CSV re-import dedups.
- **Unmapped/mapping:** punch for unmapped badge → stored NULL employee; create map → `attendance.device.map` job back-fills; overlapping map effectivity rejected (409); badge reused post-effectivity → resolves correct employee by punch date.
- **Device auth:** unknown token → 401; correct token on **other tenant's host** → 401 (cross-tenant); inactive device → 401; rotate-token → old fails/new succeeds.
- **Scope:** `GET /punches` respects data scope (branch-scoped user sees only their employees); manual punch outside scope → 403; device punches inherit device branch scope.
- **Import:** malformed rows → counted in `rejected` with `error_summary`, valid rows still accepted; unsupported tz column → row reject; large file → job completes, batch status `completed`.
- **Timezone:** `device_local` conversion correctness incl. a fixed DST-boundary case; UTC mode pass-through; `local_wall_time` preserved verbatim.
- **Overnight:** punches at 23:55/00:10 stored as ordered events with correct instants (no day logic — just storage correctness).
- **Append-only:** direct UPDATE/DELETE on `punches` via raw SQL → trigger rejects; back-fill UPDATE allowed.
- **Void:** void marks punch, viewer shows it excluded; re-void → 409.
- **M3.1 deferred obligation:** dedicated `shift_based` weekly-off + `RotationRule` resolver tests (Nth-weekday, cycle offset, boundary dates) — added in this milestone's test file, since it was recorded as an M3.2 requirement.

Unit tests: dedup-key builder, wall-clock→UTC conversion, CSV column-mapping parser, scope application.

## 9. Dependencies and risks

**Dependencies:** M3.1 merged (needs `att` schema + resolver baseline); FileService (CSV payload); jobs infra (Hangfire patterns); `users.employee_id` link (exists); `IDataScopeService` (exists); notification infra (exists). No new external packages beyond Npgsql (already present); Excel import → document as "save as CSV" or add a battle-tested parser (decision at implementation: prefer CSV-only for M3.2 to avoid a new dependency).

**Risks + mitigations:**
| Risk | Mitigation |
|---|---|
| Device clock skew produces wrong instants | `local_wall_time` preserved verbatim; `punched_at` normalizable later; skew reported in batch metadata |
| Push endpoint exposed to internet | token-only auth, tenant-host binding, rate limit, `is_active` kill switch, token rotation |
| Volume growth of `punches` | BRIN index on `punched_at`, append-only design keeps vacuum pressure low; partitioning deferred to M3.x capacity work |
| Unmapped-punch backlog | `attendance.device.map` job + "unmapped" viewer filter + count badge |
| Manual punches as integrity bypass | `note` mandatory, scoped permission, audit-sealed, distinct `source` |
| `Idempotency-Key` reuse with *different* payload | key+device+payload-hash comparison → reject 409 on mismatched reuse |
