# HR-03 — Attendance Punch Ingestion Operations (Video Script)

Status: **Script ready — not recorded** · Version: 1.0 · 2026-11-23
Audience: HR Admin, IT/device administrator, Implementation Engineer
Objective: after this video the viewer can register a biometric device, map
badge codes to employees, push/import punches, verify dedup, void a mistaken
punch, and read import history.
Prerequisites: tenant with `attendance` entitlement; org masters and ≥2 demo
employees; M3.2 build deployed.
Related manual: [attendance/punch-ingestion.md](../../attendance/punch-ingestion.md)
Estimated duration: ~9 minutes.

## Demo data required

| Item | Value |
|---|---|
| Tenant | `docsdemo` (or any demo tenant) |
| Employees | `E1001 Priya Sharma`, `E1002 Arjun Mehta` |
| Device | code `BIO-HQ-01`, timezone `Asia/Kolkata` |
| Badge codes | `42 → Priya`, `43 → Arjun`, `77` unmapped |
| CSV | `demo-punches.csv` (see script §4) |

## Demonstration sequence & narration

**0:00–0:40 — Intro.** "Attendance starts with evidence: the raw punch. Today
we'll get punches from a biometric device and a CSV file into the system —
safely, without duplicates, and in a way that can never be silently altered."

**0:40–2:00 — Register the device.** Devices → Add device. Code `BIO-HQ-01`,
name "HQ Entrance", timezone mode *Device timezone* `Asia/Kolkata`. Save.
**Show:** the one-time token banner — "Copy this now; it is stored only as a
hash. If you lose it, use Rotate token."
*Narration:* "The token authenticates the device — not a user. Treat it like a
password."

**2:00–3:00 — Map badges to employees.** Open device → User map → Add: `42`
→ Priya, effective today. Add `43` → Arjun. Leave `77` unmapped on purpose.
*Narration:* "Mapping is date-effective — the punch's own local date decides
which mapping applies, so reassignments never rewrite history."

**3:00–4:00 — Device push.** Show a `curl` push (terminal side-by-side):
`POST /api/v1/attendance/devices/BIO-HQ-01/punches`,
`Authorization: Device <token>`, three punches — `42`, `43`, `77` — timestamp
`09:0x` today. **Show:** response `accepted: 3`. Then re-send the identical
body + same `idempotencyKey` → same batch returned, counts unchanged.
*Narration:* "Replay is free — the idempotency key makes retries and offline
sync safe."

**4:00–5:30 — Raw punches viewer.** Open `/attendance/punches`. **Show:** 3
rows; `77` has blank employee. Filter by source `device`. Point out UTC
`punched_at` vs preserved `local_wall_time`.
*Narration:* "We keep the device's own wall time verbatim — calculations later
always know what the device meant, across DST and timezone edge cases."

**5:30–6:30 — Backfill.** Devices → User map → add `77 → Priya`. Run the
device-map job (or wait). Refresh punches: Priya's `77` rows now attributed.
*Narration:* "Unmapped punches are never dropped — they wait for the mapping."

**6:30–7:30 — CSV import.** Import Punches → upload `demo-punches.csv` → map
`badge` → device user code, `time` → timestamp, skip header on, device
`BIO-HQ-01`. Commit. Open Import History → batch shows accepted/duplicate
counts — rows duplicating the device pushes are counted `duplicate`, not
stored twice.
*Narration:* "Same physical punch by two paths = one record. Watch the
duplicate counter, not panic."

**7:30–8:20 — Void.** On a manual punch row → Void → reason "test entry".
Row stays, status `voided`. **Show:** trying to edit/delete is impossible —
append-only.
*Narration:* "You never delete evidence; you void it with a reason. The audit
trail keeps the who/when/why."

**8:20–9:00 — My Punches + wrap.** Sign in as Priya → `/attendance/my` → her
punches only. Punch in button records a self punch.
*Narration:* "Employees see only themselves; scoped managers see only their
org unit; unmapped punches need tenant-wide rights. That's tenant isolation
and data scope doing their job."

## Expected results checklist (for the trainee)

- [ ] Device created; token captured once; rotation works
- [ ] Push accepted; replay returns same batch; wrong-payload-same-key → 409
- [ ] Mapped/unmapped punches stored; backfill attributes later
- [ ] CSV import: accepted vs duplicate vs rejected counts correct
- [ ] Void marks a punch; original row preserved
- [ ] ESS user sees own punches only
